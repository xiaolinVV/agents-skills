# software-implementation-service-plan

## 适用场景

1. 软件实施、部署联调、上线切换、试运行、培训验收、交付计划和质量保障是评分重点。
2. 采购文件要求实施组织方案、实施进度计划、系统部署方案、数据迁移、联调测试、验收培训或资料移交。
3. 用户要求“像实施经理写的方案”“少愿景，多动作、多产出物”。

## 模板定位

1. 文档外观：正式、工程化、里程碑导向，黑灰为主。
2. 正文风格：像实施经理或交付经理写的履约方案，强调阶段、责任、产出物、检查口径和风险回退。
3. 结构策略：围绕“准备、部署、迁移、联调、试运行、切换、培训、验收、移交”组织。
4. 交付形态：DOCX 为主，实施路线图、部署拓扑、联调流程和切换回退流程作为支撑图示。

## 内容写法

1. 每个阶段必须写清输入、动作、产出物和验收口径。
2. 切换和回退要成对出现。只写上线不写回退，是实施方案里的硬缺口。
3. 涉及第三方接口、历史数据、现场网络、硬件到货、账号权限和业主配合时，写成前置条件、协同责任或风险控制。
4. 工期、人员数量、驻场天数、响应时限、质保期等数字型承诺必须来自采购文件或用户确认事实。
5. 不写“我们经验丰富、全力保障、保驾护航”等空话，用实施记录、问题台账、测试报告、验收资料等交付物说话。
6. 采购文件指定固定表单时，按固定格式保留；叙述性正文不写“本节响应评分点”。

## 图示建议

1. 实施路线图：展示准备、部署、迁移、联调、试运行、上线、验收的阶段关系。
2. 部署拓扑图：展示服务器、数据库、中间件、终端、接口和网络边界。
3. 联调流程图：展示需求确认、接口准备、联调执行、缺陷修复、复测确认。
4. 切换回退流程图：展示切换窗口、检查点、回退条件、回退动作和运行观察。

## 交付前检查

1. 每个实施阶段是否有产出物和检查口径。
2. 上线切换和回退条件是否成对出现。
3. 数据迁移、接口联调、测试验收和资料移交是否完整。
4. 第三方接口、现场环境、历史数据和业主配合事项是否写成正式边界。
5. 数字型承诺是否有来源。
6. 支撑材料位置是否精确到章节号、图号、附表号、附件号或页码锚点。
7. 图示是否服务实施理解，不是装饰图。
8. 渲染页面是否无重叠、截断、表格贴边、异常空白。
