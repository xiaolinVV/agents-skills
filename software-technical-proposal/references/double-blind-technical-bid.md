# double-blind-technical-bid

## 适用场景

1. 采购文件要求“双盲、暗标、匿名技术标、盲审、去标识化评审”。
2. 技术标与商务标、资格标、价格标需要分离，技术文件不得出现供应商身份信息。
3. 用户要求生成“暗标技术方案、双盲技术标、匿名技术响应文件”。
4. 采购文件固定格式优先；本模板只补充去标识化、弱风格和技术内容组织规则。

## 模板定位

1. 文档外观：A4、黑白灰、无 Logo、无品牌色、无可识别视觉风格。
2. 正文风格：中性、克制、技术事实导向，不写供应商叙事、公司优势和案例炫耀。
3. 结构策略：在不暴露身份的前提下覆盖技术要求、实施安排、质量保障、培训验收和服务方案。
4. 交付形态：DOCX 为主；必要图示使用单色 SVG/HTML 截图。
5. 合规优先级：去标识化高于美观。任何可能暴露主体身份的信息都不写入技术标。

## 推荐目录

按采购文件暗标格式裁剪。采购文件给出章节、字体、页边距、页眉页脚、页码、页数上限时，以采购文件为准。

1. 项目理解与技术响应
   1. 建设目标理解
   2. 技术要求覆盖
   3. 实质性条款覆盖

2. 总体技术方案
   1. 总体架构
   2. 功能模块
   3. 数据与接口
   4. 安全与部署
   5. 专项技术说明（按项目内容命名；无对应要求则删除）

3. 实施组织方案
   1. 实施阶段安排
   2. 联调测试
   3. 上线切换
   4. 资料移交

4. 质量保障与风险控制
   1. 质量控制
   2. 进度控制
   3. 风险与应急
   4. 变更控制

5. 培训、验收与服务
   1. 培训计划
   2. 验收配合
   3. 服务响应
   4. 运行支持

6. 附表
   1. 采购需求响应表
   2. 采购需求偏离表
   3. 合同条款偏离表
   4. 支撑材料索引

## 去标识化硬规则

1. 不写公司名称、简称、Logo、地址、联系人、电话、邮箱、统一社会信用代码、开户信息、网址、公众号、二维码。
2. 不写人员姓名、身份证号、证书编号、社保信息、职称证书扫描件、个人履历中可识别单位的信息。
3. 不写项目案例名称、业主名称、合同编号、验收证明、获奖证书、专利名称、软件著作权编号等可识别材料；采购文件要求证明材料时，按商务标或附件规则放置。
4. 不使用品牌色、企业模板、专属图标、专属页眉页脚、水印、背景图、彩色封面和可识别版式。
5. 清理 DOCX 元数据、图片元数据、批注、修订记录、隐藏文字、页眉页脚和文件属性中的身份信息。
6. 需要表达能力时，用“项目经理、技术负责人、实施工程师、运维工程师”等岗位角色表达，不写真实姓名。
7. 需要表达经验时，用“同类系统建设经验、同类平台运维经验、同类迁移实施经验”等泛化描述，不写可识别案例。

## 内容写法

1. 技术响应
   1. 逐条覆盖采购技术要求、实质性条款、交付期、验收、质保和服务要求。
   2. 响应内容要落到模块、流程、接口、数据、部署、测试、培训或服务动作。
   3. 偏离情况必须真实。不能为了好看把无法确认的事项写成无偏离。

2. 实施组织
   1. 写阶段、动作、产出物和检查口径，不写团队品牌和公司管理口号。
   2. 工期、质保、响应时限、人员数量等数字型承诺必须来自采购文件或用户确认事实。
   3. 第三方接口、现场环境、历史数据、网络条件和业主配合事项写成正式前置条件或风险控制。

3. 服务保障
   1. 服务响应写分级、流程、记录、复核和闭环，不写具体联系人。
   2. 驻场和值守要求按采购文件表达；未明确时不编造驻场人数或值班频次。
   3. 培训写对象、内容、方式、资料和考核，不出现讲师姓名或供应商身份。

4. 固定表单
   1. 采购文件要求响应函、偏离表、合同条款偏离表、承诺表时，保留其固定标题和列名。
   2. 表单中的“投标人、供应商、响应、无偏离”等格式用语按采购文件保留；叙述性正文不写答题卡式话术。
   3. 支撑材料位置写章节号、图号、附表号、附件号或页码锚点，不写“详见正文”。

## 图示规则

1. 默认少图、精图，只画对理解有帮助的单色图。
2. 可用图示包括总体架构图、实施流程图、联调测试流程图、服务闭环图、风险处置流程图。
3. 图示使用黑白灰，节点和线条简洁，不使用品牌色、渐变、阴影、插画、照片和可识别图标。
4. 图示中不出现公司名、人员名、案例名、Logo、水印和供应商专属术语。
5. HTML/SVG 源码放 `生成文件/double-blind-technical-bid/02-图示源码/`，截图放 `生成文件/double-blind-technical-bid/03-图示截图/`。

## 输出目录

1. 最终 DOCX 放 `生成文件/double-blind-technical-bid/01-交付文档/`。
2. 图示源码放 `生成文件/double-blind-technical-bid/02-图示源码/`。
3. 图示截图放 `生成文件/double-blind-technical-bid/03-图示截图/`。
4. 过程文件放 `生成文件/double-blind-technical-bid/04-过程文件/`。
5. 质检预览放 `生成文件/double-blind-technical-bid/90-质检预览/`，交付前按用户要求保留或清理。
6. 临时文件放 `生成文件/double-blind-technical-bid/99-临时文件/`，任务结束前清理。

## 交付前检查

1. 是否严格遵守采购文件暗标格式、页边距、字体、页码、页数和装订要求。
2. 是否清除公司名称、Logo、地址、联系人、人员姓名、证书编号、案例名、水印和图片元数据。
3. 是否清理 DOCX 属性、修订、批注、隐藏文字、页眉页脚和文件名中的身份信息。
4. 技术标是否混入商务标、资格标、价格标或供应商证明材料。
5. 采购需求、实质性要求、交付期、验收、质保和服务响应是否覆盖。
6. 偏离表、合同条款偏离表和正文承诺是否一致。
7. 数字型承诺是否有来源。
8. 图示是否单色、匿名、弱风格，且无可识别信息。
9. 支撑材料位置是否精确到章节号、图号、附表号、附件号或页码锚点。
10. 渲染页面是否无重叠、截断、表格贴边、异常空白。
