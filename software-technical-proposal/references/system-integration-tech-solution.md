# system-integration-tech-solution

## 适用场景

1. 软硬件一体交付、系统集成、网络与平台集成、接口联调、现场部署、设备安装调试和集成总包项目。
2. 采购文件要求集成边界、接口映射、网络拓扑、软硬件清单、联调测试、现场实施、切换验收和培训运维。
3. 用户要求“像系统集成总包技术负责人写的方案”。

## 模板定位

1. 文档外观：工程化、结构清晰、黑灰正式，少花样。
2. 正文风格：强调边界、对象、接口、拓扑、部署、联调、切换和验收。
3. 结构策略：围绕“集成对象、总体拓扑、接口映射、部署实施、联调测试、切换验收、运行保障”组织。
4. 交付形态：DOCX 为主；总体拓扑、接口关系图、部署拓扑、联调流程图作为支撑图示。

## 内容写法

1. 系统集成方案必须先写边界。谁提供接口、谁开放网络、谁负责设备、谁确认数据，必须清楚。
2. 不把设备清单、软件清单、接口清单和拓扑关系混在一段里。该表格化就表格化，该图示化就图示化。
3. 接口联调要写准备、联调、问题处理、复测、确认和归档。
4. 网络、现场环境、供电、机柜、链路、第三方系统和原厂支持等不可控事项，写成前置条件或协同责任。
5. 切换和回退要成对出现。只写上线不写回退，方案不合格。
6. 设备数量、接口数量、网络参数、安装位置、工期和质保等数字型承诺必须来自采购文件或用户确认事实。
7. 固定表单按采购文件保留；叙述性正文不写“评分响应、评委、为了得分”。

## 交付前检查

1. 集成对象、责任边界、第三方配合和现场约束是否清楚。
2. 接口映射、网络拓扑、部署拓扑、设备/软件清单是否覆盖。
3. 联调测试是否有前置条件、步骤、通过标准和支撑材料。
4. 切换和回退是否成对出现。
5. 数字型承诺是否有来源。
6. 支撑材料位置是否精确到章节号、图号、附表号、附件号或页码锚点。
7. 图示是否表达关系、流向和边界，不只是堆模块盒子。
8. 渲染页面是否无重叠、截断、表格贴边、异常空白。
